1 · Where Helio stands

Helio is already ahead of most independent-hotel PMSs on core operations — it has a proper front-desk flow, cashiering, night audit, housekeeping, profiles, rates & inventory, and an unusually deep 18-tab channel manager. The world-class gap is not the basics; it's the modern differentiators: an automated pricing/restrictions engine behind the screens, a real guest-experience layer (messaging, online check-in, upsell, reviews), embedded payments with OTA virtual-card handling, and 2026-grade AI/BI.

The Beds24 reality that shapes everything. Beds24 is deep on distribution primitives — pooled/allocated/virtual/bed-level inventory, occupancy/LOS/linked pricing, the full restriction set (channel-gated), 2-way sync, ~80+ channels, a built-in yield optimizer, and a complete API v2. But it is not a market-intelligence engine: competitor rate-shopping, rate-parity monitoring, RMS-grade demand pricing, content scoring, a polished unified inbox, and drift/health dashboards are not native — those you build on top. Two hard rules to design around: (1) OTA "discounts" must be sent as real prices or mapped native promos, never as discount rules; (2) API rate limit ≈100 credits / 5 min — batch calendar writes, prefer webhooks.

2 · Your current system, briefly

React 19 + Vite front-end prototype (Dexie/IndexedDB, TanStack Query with a mock fetcher, i18n, PWA). Screens present: login, property-select, dashboard, calendar, reservations, new-reservation, arrivals, check-in, in-house, guest-dashboard, departures, check-out, cashier, housekeeping, night-audit, profiles, profile-detail, reports, rates-inventory, and a channel-manager with 18 tabs (Distribution, Auto-feed, Connection, Mappings, Inventory map, Sync schedule, Channels, Content, Policies, Push & Pull, Inbox, Conflicts, Drift, Sync log, Errors, Parity, Audit, Reports). The data model already defines rate plans, restrictions, yield rules, promotions, channel content and policies — so much of the CM is drawn but not yet powered by a live rules engine. That engine is what §8 delivers.

7 · The 2026 differentiators (what makes it feel state-of-the-art)

Agentic AI on a unified data model

Not chat suggestions — agents that complete tasks within guardrails: auto rate moves, lead follow-up, guest-message drafting, auto room assignment, anomaly alerts.

Embedded payments + VCC automation

Payments as native infrastructure: tokenization, auto pre-auth/deposit charging, OTA virtual-card processing, pay-by-link, wallets, PCI DSS 4.0.1.

Unified omni-channel guest inbox

WhatsApp/RCS/SMS/OTA/email in one thread with full reservation context and AI-drafted replies. Highest-ROI guest feature to add.

Wallet-native mobile keys & online check-in

Apple/Google Wallet keys auto-issued when online check-in completes; contactless arrival with ID + payment.

AI revenue management (explainable)

Autonomous pricing within limits, with the demand signals shown. Pair Beds24's yield engine with PriceLabs/RoomPriceGenie + a rate-shopper.

Power-user UX

Command palette (Cmd-K), role-adaptive views, dark mode, offline-first PWA (you already have PWA + i18n), bento dashboards.

8 · Built this pass — the channel-manager brain (running)

The rates + channel-manager logic for Areas 1 & 2 is implemented as a running, zero-dependency engine (Node 22 type-stripping) in helio-channel-engine/. npm run demo:cm proves every option. This is the "engine behind the screens" your app is currently missing — portable into your app or a real backend.

ModuleOptions implemented & verified
cm/rates.tsoccupancy-based pricing, extra-adult, LOS tiers, derived/linked (± % and ± fixed), per-channel multiplier
cm/restrictions.tsmin/max stay, stay-through, CTA, CTD, stop-sell, release, min/max-advance + a stay validator + per-channel capability matrix
cm/yield.tsBeds24-style occupancy + lead-time auto-pricing, stackable rules
cm/promotions.tsearly-bird / last-minute / long-stay, with correct delivery mode (native OTA promo vs must-send-as-price)
cm/inventory.tspooled, allocated caps, virtual/derived, dependent (combine/split), bed-level dorms
adapters/beds24.tsBeds24 API v2 connector: batched calendar writes under the ~100-credit/5-min budget, booking-webhook normalization across OTAs

Verified demo output: BAR $285 at 2 guests → $240 at 1 guest → $310 at 3 (extra adult) → $256.50 at 5-night LOS → NREF $256.50 / B&B $300 (derived) → $336.30 to Booking.com (+18%); a 2-night stay correctly rejected against a 3-night min-stay; yield lifting +10% at 90% occupancy and cutting −12% last-minute; an Airbnb early-bird sent as a native promo while an Agoda long-stay is correctly sent as a lowered price; virtual/dependent/bed-level inventory all decrementing the right shared pool.

Honest note on the front-end: this session's sandbox blocks the npm registry (even react/vite), so your Vite app cannot be built or run here. The engine is dependency-free by design, which is exactly why it runs. Front-end feature work (the screens in Areas 3-4) ships as reviewed source that you build locally, or as the next phase once a buildable environment is available.

9 · Phased roadmap

1
Wire the CM brain into the app + Beds24 — surface occupancy/LOS/multiplier controls on the Rates screen; power the Restrictions, Yield, Promotions and Inventory tabs with the engine; push resolved ARI to Beds24 via API v2; consume Beds24 booking webhooks into the Inbox. Turns "drawn" CM options into working ones. (Areas 1-2)
2
Close the non-native CM gaps — add rate-parity monitoring (or a Lighthouse/RateGain feed), a polished unified inbox (Beds24 messaging + WhatsApp/SMS), content-completeness scoring, and drift/health dashboards from Beds24 data. (Area 2)
3
Guest-experience layer — online/contactless check-in, unified guest messaging + AI concierge, pre-arrival upsell engine, reviews/reputation, commission-free direct booking engine, loyalty. Mostly best-of-breed integrations. (Area 3)
4
Payments, ops depth & BI — integrated tokenized payments + OTA VCC automation (PCI DSS 4.0.1), split folios/AR, groups/events + BEOs, POS charge posting, pace/production/BI dashboards + conversational analytics, multi-property CRS, RBAC/2FA/SSO + public API. (Area 4)
5
2026 differentiators — agentic AI on the unified model, wallet mobile keys, command-palette UX, explainable AI revenue management, sustainability dashboard.
